# Files

Brief map of the codebase. Keep this current when files are added or change purpose.

## Root

- `README.md` Public repo front page. What Ask Jev is, how a message travels, the stack with links, features, local setup, env vars, scripts, layout, cost, credits.
- `package.json` Scripts and dependencies. `dev`, `dev:backend`, `build`, `typecheck`, `words:build`, `deploy`, `deploy:smoke`.
- `index.html` Vite entry. Loads Inter, applies the stored theme before paint, mounts `#root`.
- `public/og.png` Share card, 1200 x 630. Referenced by the Open Graph and X meta tags in `index.html`.
- `public/favicon.svg` Site icon source. Ember rounded square, compressed heavy J in obsidian as a filled path. To regenerate the fallbacks: `magick -background none -density 512 public/favicon.svg -resize 180x180 public/apple-touch-icon.png` and `magick -background none -density 512 public/favicon.svg -resize 48x48 \( -clone 0 -resize 32x32 \) \( -clone 0 -resize 16x16 \) public/favicon.ico`.
- `public/favicon.ico` 48, 32, and 16 px frames for older browsers and link previews. Generated from `favicon.svg`.
- `public/apple-touch-icon.png` 180 px home screen icon for iOS. Generated from `favicon.svg`.
- `public/icon.svg` Brand mark, 1024 box. Ember card with a 25 percent corner radius, the Archivo ExtraCondensed Black J (wdth 62, wght 900) in obsidian as a filled path, and a sulfur period. Glyph group sits inside the central 60 percent so a circle crop keeps it whole. To regenerate the PNG: `magick -background none -density 96 public/icon.svg -resize 1024x1024 public/icon.png`.
- `public/icon.png` 1024 px render of `icon.svg`. Use for the GitHub avatar and anywhere a square raster icon is needed.
- `public/logo.svg` Horizontal lockup, 879 x 240 viewBox. The mark at 200 px beside "Ask Jev" in Archivo ExtraCondensed Black as filled paths, obsidian on transparent, for the light theme (limestone or paper behind it). To regenerate the PNG: `magick -background none -density 384 public/logo.svg -resize 3000x public/logo.png`.
- `public/logo.png` 3000 x 812 transparent render of `logo.svg` for README headers and decks.
- `scripts/og-card.html` Source for the share card in the Caldera light skin, same tokens and fonts as the site. To regenerate: copy to `public/og-card.html`, open `http://localhost:5173/og-card.html` at 1200 x 630, screenshot, save as `public/og.png`, delete the copy.
- `vite.config.ts` React plugin. Reads `STATIC_HOSTING_BASE_PATH` for the static hosting deploy.
- `tsconfig.json`, `tsconfig.app.json`, `tsconfig.node.json` TypeScript project references for the app and Vite config.
- `.env.local` Written by `npx convex dev`. Holds the local deployment URL. Not committed.
- `public/robots.txt` Disallows `/admin` for every crawler.
- `.gitignore` Ignores `node_modules`, `dist`, `.convex`, env files, and the two handoff notes that name deployments (`prds/setup-domain-task.md`, `setup-off-Google-GitHub.md`).
- `.interface-design/system.md` Design system notes for agents: the two skins and their token contract, the surface shift depth strategy, and the reusable patterns (step cards with stages, ruled rows, link chips, number pairs, verdict chip and quiet tag) with their measurements. Read before UI work.
- `setup-off-Google-GitHub.md` Computer Use walkthrough for Google and GitHub sign in with Convex Auth v2 alpha on dev and prod: code changes, console steps, env vars, verification, leak check. Gitignored, names deployments and console accounts. Local only.

## convex

- `convex/convex.config.ts` Installs counters, rate limiting, agent, Auth v2 core/password/username, two OAuth components, and static hosting. OAuth owns `/oauth/google` and `/oauth/github`, core `/auth`, app `/api`, static `/`. Declares the auth keys plus five OAuth env variables.
- `convex/auth.config.ts` Custom JWT provider pointed at the deployment's own `/auth/.well-known/jwks.json`.
- `convex/auth.ts` Core and password exports plus Google/GitHub start/complete functions, exact origin allowlist, and createUser/onSignIn callbacks.
- `convex/users.ts` Password and OAuth account callbacks. Password signup guards the admin window, blocked emails, and duplicates; OAuth creates or links a verified email and rechecks identity at every sign in.
- `convex/lib/oauth.ts` Verified-email normalization/linking, admin and moderation refusal, stale-account guard, and exact-origin validation.
- `convex/oauth.test.ts` Isolated Convex tests for account linking, new provider accounts, password duplicate refusal, moderation, admin refusal, and return origins.
- `src/lib/oauth.ts`, `src/lib/oauth.test.ts` Safe same-origin next paths and typed OAuth error copy with unit tests.
- `src/lib/errors.ts`, `src/lib/errors.test.ts` `userMessage(error, fallback)`. Reads the sentence from `ConvexError.data` (the only place it survives on prod), logs anything else to the console with its request id, and returns the fallback. Every mutation catch site in the app uses it.
- `src/components/OauthError.tsx` Accessible app-wide callback error banner, including returns to question pages.
- `vitest.config.ts` Edge-runtime test configuration; `npm test` runs local tests without deploying.
- `prds/google-github-sign-in.md` Scope, verified local results, provider setup status, and remaining approval/deployment gates.
- `convex/lib/auth.ts` `getOptionalUser`, `requireUser` (throws for visitors and blocked accounts), `requireActiveUser` (also refuses paused), `isAdminUser`, `nextSequence`, `allocateHandle`.
- `convex/admin.ts` Admin only. `me`, paginated `list` by filter (all, live, blocked, hidden, private) with author handle, visibility, route, model, and answer, `search` across every status, `setHidden`, `setAnswerHidden`, `users` (paginated by status), `userTotals`, `findUsers` (email or handle prefix), `userDetail` (usage plus recent asks), `setUserStatus` (pause, block, activate; block hides public asks and records the email in `blockedEmails`).
- `convex/lib/admin.ts` `normalizeUsername`, `adminUsername` (reads `ADMIN_USERNAME`), `signupOpen`, `requireAdmin` (resolves the auth user and compares to the env var).
- `convex/schema.ts` `users` (auth username plus handle, display name, bio, links, `photoId`, `publicProfile`, `userNumber`, `status`, reason, moderated time), `sequences`, `userUsage` (asks, answers, tokens, micro USD per user), `blockedEmails`, and `messages` with `userId`, `visibility`, `threadId`, `route`, `judgeProvider`, the `answer*` fields, `archived`, `hiddenByBlock`, `wallHidden` (a signed in ask that carries a held term or blocklist word; blurred on the wall for everyone but the author and admin), `agree`, `disagree`, and `followUps` (how many turns the asker added to their own thread; the wall's Read the thread link keys off it). Indexes `by_status`, `by_session`, `by_hidden`, `by_user`, `by_user_and_archived`, `by_user_and_visibility`, `by_visibility_and_status`, and `search_text` filtered by status and visibility. `votes` (who voted which way on which ask). `threads`: one private side thread per person per ask (`messageId`, `userId`, `threadId`, `model`, `count`, `lastAt`) with `by_message_and_user`, `by_message`, `by_threadId`, `by_user`. Exports the `messageStatus`, `visibility`, `answerStatus`, and `userStatus` validators.
- `convex/questions.ts` The seven Jev questions (`reply` answers the ask: yes, no, depends, open, statement; three safety probes; mood; topic; `route` picks a model lane for signed in asks), `ROUTES` (lane, model id, label, one line why), `REPLIES`, labels, `BLOCK_THRESHOLD`, `MAX_JUDGE_ATTEMPTS`. The one file to read to understand the policy.
- `convex/messages.ts` Public API. `send` (visibility; visitors go through `parseMessage` and the held terms gate, accounts through `parseOpenAsk` with a held term or blocklist word setting `wallHidden` instead of rejecting; anonymous or signed in rate limits, usage row, insert, schedule judge), `retry`, `wall` and `search` (public live rows only, `wallHidden` rows dropped from search unless the viewer may reveal), `get` (one ask with thread access for the ask page), `mine` (your session's or account's recent asks). `toPublic` takes the viewer and computes `masked`: admin hidden, or `wallHidden` and the viewer is not the author or admin. Masked rows blur the text and drop the answer; the projection prices the answer and attaches the author. `overrideReply` is an internal mutation for CLI backfills.
- `convex/judge.ts` `run` internal action asks Jev through `lib/jev.ts` with retries (a `JevUnavailableError` publishes unjudged with no retry) and reads the runner up (`secondChoice`) out of the reply Choice probabilities. `record` applies the threshold, stores reply, confidence, runner up, route and provider, bumps counters and the user's Jev tokens, and schedules `answer.run` for live signed in asks.
- `convex/votes.ts` "Was Jev right?" `cast` (live, judged, not hidden, reply in yes/no/depends; same vote takes back, other vote flips; patches `agree`/`disagree` on the row and bumps `voteAgree`/`voteDisagree`; IP plus `vote` bucket, returns `retryAfterMs` instead of throwing), `mine` (the viewer's votes by `voterKey`, take 500), `voterKeyFor` (`u:<userId>` or `s:<sessionId>`), `deleteVotesFor` for account deletion.
- `convex/lib/jev.ts` One door to Jev. Default is the Convex AI Gateway Decisions endpoint (`POST /alpha/decisions`, model `typesafe/jev-1.13`) on a `getServiceToken("ai-gateway")` token with the System One body unchanged. `JEV_PROVIDER=typesafe` pins TypeSafe direct first. Whichever is primary, the other is tried once on failure when configured (`jevProviderOrder`). `JevUnavailableError` when the gateway refuses the deployment and there is no key. `jevConfigured`, `jevProvider`, `askJev` (returns `provider`, `latencyMs`, gateway `costUsd`).
- `convex/jev.test.ts` Vitest for the provider order, the Decisions request shape, `JEV_GATEWAY_URL` override, both fallback directions, and the unavailable path, with `getServiceToken` and `fetch` mocked.
- `convex/answer.ts` Model answers through the Convex AI Gateway with `@convex-dev/agent`. One cached `Agent` per model. `run` creates the thread, streams the first answer, mirrors text onto the row every 350ms, records tokens. Follow ups: `laneFor` decides `own` (the asker, answer done) or `side` (anyone else signed in, on any live ask) or null (held, hidden, masked); `followUp` saves the turn in the right thread, opening a side thread in the `threads` table on the first send with `sideSystem` (ask text, verdict, confidence, short answer) as the model's context, and bumps `followUps` on the row in the own lane; `reply` streams the model turn with an optional `system`; `readAccess` gates `listMessages` (owner thread public when the ask is, side thread for its owner and the admin only); `myThreads` lists the viewer's side threads for `/me`; `deleteSideThreadsOn` and `deleteSideThreadsFor` clean up on ask and account deletion; `recordUsage` bumps counters and the user's usage row.
- `convex/profile.ts` Accounts. `me`, `update` (handle, name, bio, links, public flag, validated), `generateUploadUrl` and `setPhoto`, `byHandle`, `publicAsks`, `history` by filter, `setVisibility`, `setArchived`, `remove` (deletes the thread too), `exportData` (newest 1,000 asks), `deleteAccount` (private asks and threads deleted, public asks detached, usage, daily rows, photo, and username removed). `stats` reads up to 400 `userDaily` rows for a handle and returns the days plus reply, topic, and model totals; private counts are zeroed for anyone but the owner or the admin. `byHandle`, `stats`, and `publicAsks` all show a private profile to its owner.
- `convex/migrations.ts` One time internal functions run with `npx convex run`: `backfillVisibility` marks old rows public, `backfillUsers` gives existing accounts a number, handle, and status, `backfillDaily` clears and rebuilds `userDaily` from the messages table in pages. `backfillReply` (an action) pages live rows judged before Jev's `reply` question existed through `pageLiveWithoutReply`, asks Jev the one `reply` Choice per row, and writes `reply`, confidence, and runner up through `setReply`, which skips rows that gained a reply meanwhile and adds the tokens to the global counters only. `dryRun` counts, `limit` caps a run and the log prints the cursor to resume from. All run on dev.
- `convex/migrations.test.ts` Vitest with `convex-test` and the sharded counter component registered: `backfillReply` dry run makes no Jev call and counts one missing row; a real run posts only the `reply` question, fills the missing row and nothing else, leaves the row's own tokens alone, and adds spend to the `inputTokens` counter; a `limit` hit logs a resume cursor; a Jev failure is counted and the row stays unset.
- `convex/stats.ts` `counts`, `cost` (Jev spend plus answers, answer tokens, answer USD, per answer), `agreement` (agree, disagree, total, rate or null from the two vote counters), `gate` (configured and which provider), `mood` (mean Score over recent public live posts).
- `convex/lib/pricing.ts` Jev list price ($0.042 per million input tokens, output free), `costUsd()`, a per model price table for the gateway models, `answerMicroUsd()`, `microToUsd()`.
- `convex/lib/usage.ts` `bumpUsage`, adds to a user's `userUsage` row and creates it on first use. `bumpDaily` does the same for the `userDaily` row keyed by `dayKey(ms)` (UTC date), adding numbers and incrementing the reply, topic, and model records.
- `convex/lib/limits.ts` Plain numbers shared with the browser: anonymous five a minute, signed in twenty, two hundred answers a day.
- `convex/lib/words.ts` Shared message parser. Visitors: `parseMessage`, `MIN_WORDS` 3 to `MAX_WORDS` 15, gate 1 a profanity blocklist (`obscenity`) that masks as `***`, gate 2 the allowlist plus five demo words. Accounts: `parseOpenAsk`, `MAX_OPEN_WORDS` 60 and `MAX_OPEN_CHARS` 600, no allowlist, and a `profane` flag instead of a rejection. `countOpenWords` and `hasProfanity` back the composer's live note. Used by both browser and server.
- `convex/lib/safeWords.ts` Generated. 12,530 human verified plain English tokens as a `Set`.
- `convex/lib/typesafe.ts` Typed fetch client for `POST https://api.typesafe.ai/v1/systemone`. Question and answer types.
- `convex/lib/counters.ts` `ShardedCounter` instance, keys `live`, `blocked`, `submitted`, `judged`, `inputTokens`, `outputTokens`, `answers`, `answerInputTokens`, `answerOutputTokens`, `answerMicroUsd`, `voteAgree`, `voteDisagree`, `GOAL`, and `START_MS` (when the run to one million began, stored as UTC).
- `convex/lib/heldTerms.ts` Server only. `isHeldTopic` reads a comma separated `HELD_TERMS` env var and matches whole words and whole phrases on word boundaries. Text is lowercased and stripped of punctuation before the match. For a visitor `send` stores a match as `blocked` without calling Jev. For an account `send` sets `wallHidden` and Jev still answers. The list is never in the repo or the browser.
- `convex/lib/rateLimits.ts` `RateLimiter` instance. Anonymous: `ip` fixed window and `post` token bucket, five a minute, burst three. Signed in: `userIp` and `userPost`, twenty a minute, burst ten, keyed by user id. Answers: `answer` twelve a minute, `answerDaily` two hundred a day. Votes: `vote` thirty a minute, burst ten, keyed by voter.
- `convex/tsconfig.json` TypeScript config for the Convex runtime.
- `convex/_generated/` Generated by `npx convex dev`. Do not edit.
